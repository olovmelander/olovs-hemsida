# Norrfällsviken Lantmäteriet orthophoto intake

The live STAC check on 2026-09-09 confirms **orto-u2-2024** is the newest
published imagery covering this course. Every acquired pixel comes from the
**2024-06-27** flight, confirmed by intersecting each review window with the
published `flygbild` source-image mosaic polygons. The catalogued source tile
is `o69875_6775_25_mr24`, RGBI at **0.16 m** ground sample distance in EPSG:3006.
It covers the whole played course, clubhouse, range, Storsanden beach and the
adjoining sea/forest/roads/trails. The broad original discovery additionally
selected 2012 imagery over outer sea; this review needs none of that fallback.

The source byte-range request returned HTTP 206, the correct TIFF signature
and the advertised 646,553,611-byte length. Its native 15,625 × 15,625 pixel
grid and `[677500, 6987500, 680000, 6990000]` metre bounds match the catalog.
The bounded acquisition retains 23 windows containing 112,862,612 pixels:
22 native windows and one 0.8 m overview. All pixels are valid. The retained
GeoTIFF windows total 333,114,317 bytes; repeated overlap pixels are expected.

The acquisition verifier passed all 23 raster and RGB hashes, exact grid
bounds, EPSG:3006, explicit RGBI interpretation, independent validity masks,
PNG/TIFF RGB equality, pixel-centre worldfiles, complete source-date coverage
and byte-for-byte agreement across all 75 overlapping native window pairs.
These checks establish coordinate consistency. They do not establish the
absolute survey accuracy of an image or accept a mapped feature boundary.

## Local imagery and coordinates

Raw imagery is ignored under `nvgkbuild/cache/lm-ortho/`:

- `norrfallsviken-01-hole` through `norrfallsviken-18-hole`: full-hole native windows.
- `facilities-range`: clubhouse, practice greens, range, pads and nearby roads.
- `storsanden-beach`: north beach, dunes, woodland and beach access.
- `east-coast-north` and `east-coast-south`: adjoining shore, forest and trails.
- `ground-overview`: 1979 × 2314 pixels at 0.8 m.

Each has a georeferenced `.tif`, lossless RGB `.png`, `.json` hash/grid ledger,
pixel-centre `.pgw` and a baseline `-overlay.png`. RGBI band 4 is near infrared,
not transparency. Acquisition overlays show existing course geometry, and
the four additional context windows have no baseline ring overlays.

Overview pixel-edge bounds are `[678172, 6987820.8, 679755.2, 6989672]`.
For every acquired image, the pixel-edge mapping is:

```text
E = minE + column * resolution
N = maxN - row * resolution
```

Add 0.5 to column and row when mapping pixel centres. The local source model
uses origin 62.98250° N, 18.53250° E. Its stored `mPerLon=50568.51` and
`mPerLat=111320` provide the exact runtime inverse after PROJ EPSG:3006→WGS84:

```text
x = (longitude - 18.53250) * 50568.51
z = (62.98250 - latitude) * 111320
```

The intake plan follows `nvgkbuild/lib.mjs`'s unrounded cosine-derived longitude
scale; its difference from the stored model scale is below 0.1 mm over the
review window. No image shift, rotation or scorecard-distance fitting is used.

`lm-review-crop.py` makes bounded panels with a retained transform from the
**displayed pixel edges** directly to EPSG:3006. Cropping and resizing are
already included. Use original-resolution image viewing when reading trace
coordinates; any viewer resize must be accounted for.

## Reproduce

Use the ignored Python environment at `geobuild/cache/ortho-venv`, containing
numpy, Pillow, pyproj, rasterio and shapely. Supported `LANTMATERIET_*`
environment variables or the existing ignored `.env` supply credentials.
The scripts never serialize credential values or provider error headers.

```powershell
node nvgkbuild/mapping/lm-ortho-discover.mjs
geobuild/cache/ortho-venv/Scripts/python.exe nvgkbuild/mapping/lm-ortho-acquire.py
geobuild/cache/ortho-venv/Scripts/python.exe nvgkbuild/mapping/lm-ortho-capture.py
geobuild/cache/ortho-venv/Scripts/python.exe nvgkbuild/mapping/lm-ortho-verify.py
geobuild/cache/ortho-venv/Scripts/python.exe nvgkbuild/mapping/lm-review-crop.py norrfallsviken-01-hole --max-size 1600
```

The plan in `geo_data/course-v2/norrfallsviken/reference/` is pinned to the
pre-review model. `--replan` deliberately replaces it. `--only` retries selected
windows and `--probe-only` tests access; both preserve the complete acquisition
ledger by writing a separate result under the ignored cache. Verified cached
windows are reused by request and file hashes. Shared authorization and
bounded-byte validation come from `visbybuild/mapping/lm_ortho.py`.

The same reference directory contains the live catalog, pinned plan,
acquisition ledger, source-image capture evidence and offline validation
under the `lm-ortho-*-2026-09-09.json` names. Imagery remains outside Git and
outside runtime textures. Attribution: Ortofoto Nedladdning © Lantmäteriet,
bearbetad information, CC BY 4.0; the acquisition ledger retains the terms URL.

The source can resolve platform outlines, putting surfaces, roof footprints,
shore edges and many paths. It cannot by itself establish current daily tee
marker positions, the clubhouse facade dimensions or changes after June 2024,
including the club's proposed September 2026 redevelopment.
