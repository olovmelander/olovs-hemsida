# Species from evidence, revised after review: SLU stand prior at its own resolution inside a v2 stand field, NMD held-out gate, shore rule kept verbatim, species-blind placement fingerprint

## Summary
The recommendation stands: derive a per-cell species prior (pine/spruce/broadleaf) from SLU Skogskarta 2015 volumes (12.5 m, CC0 via Skogsstyrelsen, streamed by range from three county zips at ~36 MB total), calibrate it against NMD 2018 classes fetched point-by-point from the Naturvårdsverket WMS, sharpen individuals with a bounded per-crown likelihood from the leaf-off 2025-05-12 Esri imagery, and reject laser intensity (16-19x scale between the two campaigns) and crown shape (unimodal, campaign-biased) as species evidence. The review found the spec's data layout, gates and invariants unsound in twenty places and every one is folded: the stand field v2 now carries the prior as two trailing planar planes at 16 m (the prior's own resolution; 32 KB raw for the whole ground, so the byte budget holds by construction where the review's own measurement showed the 6-byte interleave costing +338-343 KB and planar-at-4 m +178-193 KB); the shore-birch rule is kept verbatim as a pre-test so the default prior reproduces today's chooseSpecies bit for bit (the floor formulation changed 43 percent of shore trees); the byte pair (0,0) is a "no prior" sentinel so unmeasured cells fall to the runtime default instead of reading as certain broadleaf, and the quantised default no longer flips 0.22 percent of trees; boot-profile gains species-blind placement and rendered-size fingerprint axes because the existing axes hash species and would fail by construction; draws are gated as a delta against the same build with the new ?speciesPrior=off switch (which needs a main.js edit, now listed) rather than a stale literal 36; the publish path lists all twelve files that hard-code the v1 feature strings (graph-node, chunk-node, decode-web, schema.mjs, both JSON schemas, course-v2.node-test) so verifyAssetGraph, check-app-build and the freeze test accept a v2 stand chunk; the "byte-identical without a prior" invariant is restated as chunk bytes only, since the version bump and the null-centroid fix (25,697 of 44,961 cached candidates, filtered in crownStatistics where the cells field exists) change candidates.json on purpose; and the tautological runtime-vs-prior gates are supplemented by a held-out NMD accuracy gate on 1,000 stand-cell centres never used in the fit, with spatial folds and a 30-sample bin rule. Phase 2 (the legacy lattice outside coverage) is re-sized from the committed phase-4 record (19,664 trees on v2, 54,601 on gpk1), samples an offline raster compiled into legacy world coordinates through the same legacyGridBridge constants the runtime uses, and states that it changes legacy tree heights as well as species.

## Risks
- Esri World Imagery is refreshed without notice; the per-crown colour term is valid only for the leaf-off 2025-05-12 Vivid block, so the identify DATE/BlockName check must run before every compile and the term must be disabled on change — the spec makes this a rule but a compile run with a stale crown-features.json would still carry the old fit unless the features file records the block it was built from (it does, by spec).
- SLU Skogskarta 2015 is eleven years old: 4,296 of 25,511 window cells carry zero volume, 388 of them under >= 50 % laser canopy, and the CHMv2 felling blocks post-date it; those cells carry the sentinel and render as today's default, not as evidence.
- The calibration was fitted on 713 NMD-labelled crowns from one course, mostly resolved edge/open trees, while 94 % of coloured trees are stand trees under closed canopy; the held-out stand-cell gate (>= 0.70 agreement on top-prior >= 0.8 cells) is the only measurement of that transfer and its threshold is a first value, not a calibrated one.
- The 16 m prior planes deviate from the review's proposed planar-at-4 m layout; the byte bound is by construction (32,768 B raw) but the nearest-neighbour 12.5 -> 16 m resample softens stand edges by up to 8 m, and the held-out gate is the only thing that would show it mattering.
- Schema changes (stand-field-u8-v2, object-registry-json-v2) touch the validator, both decoders, the graph verifier, both JSON schemas and the feature-list test; an old app build refuses a republished ground (fail-closed by design), so app and ground must ship together, and check-app-build must be green on the synthetic v2 fixture before the republish.
- Reading the SLU TIFFs needs a hand-written TIFF-LZW decoder in Node (no GDAL/Python here); validated only on this file's layout (RowsPerStrip 1, predictor 1, LE, int16) and the reader asserts every tag.
- A changed prior changes which trees are birch/spruce/pine everywhere inside coverage, so the goldens, the phase-4 species counts and the two existing fingerprint axes change on purpose; only the new placement/sizes axes prove that nothing else did.
- The null-centroid filter in crownStatistics changes candidates.json, evidence.candidates counts and the review overlays; the freeze test tolerates it but any downstream consumer of candidate keys ordering must be regenerated.
- NMD 2018 GetFeatureInfo is a public INSPIRE view service; ~4,500 one-off point queries (3,502 calibration + >= 1,000 held-out) must stay at concurrency <= 2 with a cache, and the 2018 layer could be withdrawn once 2023 v2.x is fully served.
- Phase 2 changes legacy tree heights as well as species (hashed within a per-species range), which is a visible change outside the 2 km coverage; it is reported, not gated, and needs its own owner review.

## 1. Data contract

### 1.1 Group vector, default, sentinel
`prior = [pine, spruce, broadleaf]`, each in [0,1], sum 1 (±0.01 after quantisation). Runtime index mapping (`apps/golf/src/engine/v2-vegetation.mjs:39`, `SPECIES_INDEX = { spruce: 0, pine: 1, birch: 2 }`): pine→1, spruce→0, broadleaf→2.

- `SPECIES_PRIOR_DEFAULT = Object.freeze([0.56, 0.27, 0.17])` — today's thresholds in `chooseSpecies` (`v2-vegetation.mjs:198`: `r < 0.56 ? pine : r < 0.83 ? spruce : birch`). The runtime compares `r` against the cumulative literals `0.56` and `0.83` (not `0.56 + 0.27`, which is `0.83 + 1.1e-16` in doubles — harmless for a 32-bit hash but stated).

**Payload layout (v2):** bytes `[0, 4·count)` are the v1 interleaved block, **byte-identical to what v1 would encode for the same field**; then a pine plane of `pw·ph` bytes and a spruce plane of `pw·ph` bytes, row-major north-to-south / west-to-east, where `pw = width·cellMetres / 16`, `ph = height·cellMetres / 16` (a 256 m tile of 64 × 64 4 m cells → 16 × 16 prior cells). `decodedBytes = 4·count + 2·pw·ph`. Encoded per tile: 4,096 × 4 + 512 B.

**Why 16 m planes and not the review's 6-byte or planar-at-4 m layout.** The review measured, with `chunk-node.mjs`'s exact codec (deflateRaw level 9 / memLevel 9, lines 32–37) over the 64 published stand chunks (262,144 cells, v1 payload deflate 501,331 B): 6 B interleaved +337,698 … +343,446 B; v1 block + two 4 m planes +177,998 … +192,964 B; separate stream +167,443 B. The interleave penalty is structural (a 2-byte repeat behind four noisy bytes never reaches deflate's 3-byte match), and the review's planar fix would fit the 950 KB gate with ~20 KB to spare. But the prior is a 12.5 m product: storing it per 4 m cell replicates each value ~10× and buys nothing. At 16 m the raw prior for the whole ground is 64 × 512 = **32,768 B**, and deflate cannot exceed raw by more than 5 B per 64 KB stored block, so the stands delta is **≤ ~33 KB + header growth (~150 B × 64 ≈ 10 KB) before any compression**. Nearest-neighbour resampling 12.5 → 16 m takes the 12.5 m cell under each 16 m cell centre; the calibration's per-cell semantics are unchanged (the held-out gate in §4.4 is measured on exactly those resampled cells). The stand block stays byte-identical to v1 so `decodeStandField` on a v2 payload reads the first `4·count` bytes exactly as today.

### 4.2 Calibrated cell prior (rules v1)
For a 12.5 m cell with volumes `t, g, b`:
1. `tot = t + g + b`. If `tot < 5`: nearest cell with `tot ≥ 5` within 3 cells (flag bit1); if none, write the sentinel (0,0) and flag bit2. Measured: 4,296 zero cells of 25,511 with laser data; 3,182 are laser-bare (< 10 % canopy) and 388 hold ≥ 50 % canopy → bit3 on those.
2. `pb = b / tot`. Broadleaf is piecewise-linear through the bin centres of the measured P(NMD 115/125 | pb bin), **after merging any bin with n < 30 into its lower neighbour** (`binMinimum: 30`): the measured bins 0–.2 (n 308) 0.08, .2–.4 (142) 0.58, .4–.6 (163) 0.80, .6–.8 (90) 0.91 and .8–1 (10) 1.00 become (0.1→0.08), (0.3→0.58), (0.5→0.80), (0.8→0.92) with the merged top bin `(0.91·90 + 1.00·10)/100 = 0.92` at centre 0.8, flat beyond; clamped to [0.03, 0.97]. The first draft wrote the n = 10 bin's 1.00 into the rules; its exact 95 % lower bound is ≈ 0.69, which is why the rule now exists. The bins are re-derived at compile time from `nmd2018-crown-classes.json` and the fit is **reported on spatial folds** (fold = the 256 m finest tile containing the crown, 64 tiles → 5 folds by tile index modulo 5) beside the in-sample bins.
3. Conifer split `s = g / (t + g)` (0.5 if `t + g = 0`); `spruceShare = clamp(0.5 + 2.0·(s − 0.465), 0.05, 0.95)`, the stretch measured between NMD-pure stands (tallskog cells s = 0.26 → 0.09; granskog s = 0.67 → 0.91; 0.465 is the window's conifer mean).
4. `pine = (1 − broadleaf)·(1 − spruceShare)`, `spruce = (1 − broadleaf)·spruceShare`; quantise with broadleaf as the remainder so the triple sums to 255; assert the pair is not (0,0).
Contorta and ädellöv are absent in this window (NMD 116/117 absent from the 1,052 sample; the SLU contorta layer is unused); rules v1 state this and a non-zero share on another ground is a recorded decision.

### 4.3 Per-crown likelihood (individuals only)
Features from §3.3 plus shape from the cached CHM (`chm-<campaign>.f32`): `fill` = mean `clamp(h/H)` over the disc of radius R; `topFrac` = share of disc cells with `h ≥ 0.8H`; shape z-scored per campaign (north bias measured: tallskog 0.483 S vs 0.544 N; triviallöv 0.553 vs 0.575). Fit: 2-class logistic (NMD 115/125 vs 111–114/121–124; n = 713 today) on `[z(yel), z(lum), z(gcc), z_camp(fill)]`, **spatial 5-fold CV by 256 m tile**; coefficients and CV AUC in the evidence; enabled only if CV AUC ≥ 0.80 (single-feature AUCs today yel 0.879, lum 0.862, gcc 0.871, fill 0.635–0.679; hand-weighted 0.867). Update: `odds_broadleaf ×= exp(clamp(L_b, −1.386, +1.386))` (≤ ×4); conifer split `odds_spruce ×= exp(clamp(0.5·z(gcc) − 0.4·z(lum), −0.69, +0.69))` (≤ ×2). Intensity is never a feature.

## 6. Runtime — `apps/golf/src/engine/v2-vegetation.mjs`

### 6.1 `chooseSpecies` — the shore rule stays verbatim
Replace 196–199 with:
```
export const SPECIES_PRIOR_DEFAULT = Object.freeze([0.56, 0.27, 0.17]);
function chooseSpecies(r, shoreDistance, prior = SPECIES_PRIOR_DEFAULT) {
  if (shoreDistance !== null && shoreDistance < 28 && r < 0.7) return SPECIES_INDEX.birch;   // verbatim, first
  const pine = prior === SPECIES_PRIOR_DEFAULT ? 0.56 : prior[0];
  const conifer = prior === SPECIES_PRIOR_DEFAULT ? 0.83 : prior[0] + prior[1];
  return r < pine ? SPECIES_INDEX.pine : r < conifer ? SPECIES_INDEX.spruce : SPECIES_INDEX.birch;
}
```
With the default this is today's function bit for bit, shore included. The first draft's floor (`broadleaf = max(broadleaf, 0.7)`, renormalised) was wrong: today a shore tree is birch for r < 0.7, spruce for 0.7 ≤ r < 0.83 and birch again above — 87 % / 13 % / 0 % — while the floor gave 70 / 9.8 / 20.2 and changed 43 % of shore trees under the default prior alone. Shore trees are numerous because `shoreDistanceAt` (`main.js` working tree 3572, `(x, z) => SHORE(x, z)`) is supplied for every v2 instance. A raised broadleaf share near water under an SLU prior, if wanted, is a compiler term in §4.2, never a runtime rule.

### 6.2 Where each instance's prior comes from
- `cellPriorFromField(field, column, row)`: `null` if the stand cell is unmeasured (`flags & STAND_FLAG_MEASURED` = 0) or the field has no `prior`; else read `prior.pine/spruce` at `(floor(column·cellMetres/16), floor(row·cellMetres/16))`; return `null` on (0,0); else `[p/255, s/255, max(0, 1 − p/255 − s/255)]`.
- Individuals (220–238): `prior = record.speciesPrior ?? cellPriorFromField(tile.stands, …) ?? SPECIES_PRIOR_DEFAULT`, the cell found from the record's easting/northing in its tile; `r` stays `stringHash(record.id) / 2^32` (227). Unmeasured cells under individuals exist (`stand-fields.mjs:153` counts `measuredCells` before the extent `continue` at 154, but `measured[output]` at 160–161 needs a quarter of the 1 m cells), which is why the `null` chain matters.
- Stand trees (239–281): `prior = cellPriorFromField(field, column, row) ?? SPECIES_PRIOR_DEFAULT`; `r` stays `hash01(ce, cn, 16 + k·5)` (273). **No position, height, radius or rotation hash changes.**

### 6.3 Statistics
`stats` (284–297) gains `species: { individuals: [n0, n1, n2], stand: [n0, n1, n2] }` and `expectedSpecies: [e0, e1, e2]`, the sum over planted instances of the per-instance probability vector **after the shore rule**: for an instance with shore < 28 m, P(pine) = max(0, pine − 0.7), P(spruce) = max(0, min(pine + spruce, 1) − max(0.7, pine)), P(birch) = 1 − the others; otherwise `[pine, spruce, broadleaf]`. With ~60 k draws the binomial deviation is ~0.2 pp, so the ±2 pp check in §10.5(b) is a runtime self-check and is labelled so.
