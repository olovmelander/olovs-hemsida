# Johannesberg orthophoto review source

Live Lantmäteriet STAC discovery on 2026-09-09 selected `orto-o2-2025`,
the newest campaign with complete ground coverage. The 2026-09-04 discovery's
selected assets are unchanged. Four authenticated source COGs cover the review
windows; published mosaic-source polygons identify **2025-06-14** as the capture
date throughout every window.

The acquisition contains 74 windows: an estate overview at 0.8 m, all 27 complete
holes at 0.32 m, and 46 native 0.16 m windows covering all 27 green/bunker areas,
supplemental greens and tees, and estate infrastructure. RGBI
GeoTIFFs, RGB PNGs, overlays and pixel-centre PGW worldfiles remain in the ignored
`johannesbergbuild/cache/lm-ortho/` directory. They are tracing sources, not runtime
textures. Public provenance lives under
`geo_data/course-v2/johannesberg/reference/lm-ortho-*-2026-09-09.json`.

Reproduce with the ignored Python environment containing rasterio, numpy, pyproj,
Pillow and shapely:

```powershell
node johannesbergbuild/mapping/lm-ortho-discover.mjs
upsalabuild/cache/review-venv/Scripts/python.exe johannesbergbuild/mapping/lm-ortho-acquire.py
upsalabuild/cache/review-venv/Scripts/python.exe johannesbergbuild/mapping/lm-ortho-capture.py
upsalabuild/cache/review-venv/Scripts/python.exe johannesbergbuild/mapping/lm-ortho-verify.py
```

`--only eighteen-01-surfaces` selects one window; `--probe-only` checks bounded
authenticated byte access. `--plan-only` writes a plan without fetching pixels.
Acquisition reuses the pinned baseline plan by default. `--replan` explicitly
replaces it from current geometry and removes supplemental windows, so do not use
that option while applying reviews pinned to the current plan. New review windows
can be added without changing baseline geometry:

```powershell
upsalabuild/cache/review-venv/Scripts/python.exe johannesbergbuild/mapping/lm-ortho-extra.py --window nine-03-actual-green,678665.92,6626182.08,90
```

Run capture and verification after adding windows. Credentials come from the
existing `LANTMATERIET_*` environment or ignored `.env` and are never printed.

`boundsEpsg3006` contains pixel edges `[minE,minN,maxE,maxN]`. For a native pixel
centre, `E=minE+(column+0.5)*resolution` and
`N=maxN-(row+0.5)*resolution`. For tracing a continuous image coordinate, use
`E=minE+x*resolution` and `N=maxN-y*resolution`. Use pyproj for EPSG:3006 ↔ WGS84;
then the legacy frame is `x=(lon-18.19202)*111320*cos(59.72733°)` and
`z=-(lat-59.72733)*111320`. The JSON model's rounded `mPerLon` is not the authoritative
inverse of `johannesbergbuild/lib.mjs`.

Verification checks every planned window, source/grid and image hashes, valid
pixels, exact PNG↔GeoTIFF RGB equality, worldfile pixel centres, capture footprint
coverage and persisted RGBI semantics. The fourth band is near infrared, never
opacity; GeoTIFF update mode is required here to persist that interpretation.
Ground sample distance and internal grid consistency do not establish absolute
horizontal accuracy, and source acquisition does not accept any new outline.

The estate review accepts four changes: the practice putting boundary, the small
range-shelter roof, the surfaced club-to-range path and the hole-18 causeway.
Near-play inherited water-bank outlines and measured water levels are retained
after imagery review. Roof overhang, shaded paths and partially obscured range
mats do not support finer changes from this source alone.

The vegetation audit found no individual tree centres inside accepted greens,
tees or fairways. Four 4 m stand cells visibly occupying clear turf were excluded
through `publish-reviewed-stand-exclusions.mjs`. Its source-pinned review and
publication report document the four changed flag bytes; individual trees,
other canopy measurements, terrain, frame and routing remain intact. The audit
report describes the graph before those exclusions, while the publication report
records their resulting graph references.
